# Instructions pour la documentation (Version Finale)

## Règle d'or sur le code obsolète
- Tu remarqueras la présence de dossiers nommés `console/` dans `controller/` et `view/`. 
- **Considère ces dossiers comme étant obsolètes**. Ils représentent une itération passée du projet.
- NE DOCUMENTE PAS la logique de ces dossiers, sauf si cela sert à expliquer une évolution architecturale (ex: "Passage d'une interface console vers une architecture MVC avec JavaFX").

## Consignes de rédaction
- Utilise un ton professionnel pour un rapport de SAÉ (BUT Informatique).
- Concentre-toi sur la couche `model/` et `controller/gui/` qui constituent la version finale du produit.
- Structure chaque section avec :
  - **Objectif** : Ce que cette partie apporte au jeu.
  - **Structure** : Les classes clés.
  - **Logique métier** : Comment les données interagissent.
  - **Évolution** : Mentionne comment l'architecture a été pensée pour être découplée de la vue (notamment via les contrôleurs).
